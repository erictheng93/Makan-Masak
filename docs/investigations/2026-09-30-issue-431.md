# Issue #431 稽核紀錄

## 根因

1. POS 頁面呼叫未實作的 `/pos/promotions`、`/pos/registers/:id/cash-movements`、`/pos/registers/:id/stats/daily`。前端測試直接模擬這些網址成功，未驗證 Hono 實際路由，因此三個 404 未被攔截。
2. 開班後 `expectedAmount` 沿用開班值；現金對帳只在結班時計算。畫面沒有可靠的即時抽屜餘額。
3. 班次累計與店家日曆日不是同一個統計範圍。跨午夜的班次不能整筆當作今日營收，市場結帳子付款也不能重複計數。
4. 原促銷 UI 並未連接優惠券後端，訂單只有單一優惠碼，無法保存多券逐筆折扣。

## 修正與確認範圍

- 現金異動改用既有 shift 路由，處理回應結構、分轉元與收支正負號；今日統計使用既有日報路由，加上收銀機篩選及店家時區。
- 今日營收按完成付款時間計算；市場結帳計一次。現金餘額與結班共用對帳公式，排除非現金付款、未核准異動及重複計入的銷售紀錄。
- POS 促銷共用 CouponService，店主／管理員可以管理，收銀員只能讀取；保留模組授權及店家隔離。
- 既有優惠券編輯器增加互斥券設定，保留有效期、總張數、每人限用次數；刪除已被引用的券不會讓其他券無法編輯。
- 顧客可選多張券或輸入代碼，移除與修改購物車會重新預覽；過期回應不會覆蓋新選擇，未完成有效預覽不能提交。
- 後端重新驗證並計價：依選取順序先算百分比，再扣固定額；任一方向互斥即拒絕，折扣不超過商品小計。券的最低消費以原商品小計驗證。
- 訂單保存逐券名稱、代碼及實際折扣快照；POS 與顧客訂單頁顯示同一份明細和最終應付金額，保留舊單碼相容性。
- 多券名額部分取得失敗或訂單寫入失敗時，嘗試歸還所有已取得名額；取消訂單與釋放優惠券用量在同一 D1 batch 內完成。

## 稽核案例

| 案例 | 預期結果 |
| --- | --- |
| 100 元，選取固定 5 元、10%、20% | 計算順序 10%、20%、5 元；折扣 10、18、5；應付 67 |
| A 排除 B，B 未排除 A | 不可併用，無訂單／用量部分寫入 |
| 券到期、額滿、重複代碼或跨店代碼 | 後端拒絕，不信任前端預覽金額 |
| 第二張券取得名額失敗 | 第一張券名額歸還 |
| 取消多券訂單 | 所有用量釋放，重複取消不重複退回 |
| 刪除 B，再編輯原本排除 B 的 A | 可保存，亦可清除互斥設定 |
| 開班 1000，現金收入 200，卡收入 310，支出 50 | 抽屜預期現金 1150，今日營收 510 |
| 班次跨午夜，昨天有額外付款 | 今日僅計今日完成付款 |

已使用優惠券的訂單禁止追加／修改商品數量，須取消後重新下單，避免已保存折扣與最低消費、適用品項或用量失去一致性。
