# Backend Rust Refactor — Documentation Set

Reference documentation of the current TypeScript backend, written to support a
future rewrite in Rust. Every document was generated by reading the source
code directly (tests excluded), then reviewed and spot-verified against the
code. Claims about bugs and dead code below were individually confirmed.

> Generated 2026-07-24 from the state of `main` at commit `99299b41`.
> Every document then went through an **adversarial verification pass**
> (one dedicated reviewer per doc, route tables reverse-checked against
> route files, schema claims against Drizzle definitions, dead-code claims
> re-grepped); all confirmed findings were fixed in place, and new bugs the
> pass surfaced were added to the inventory (items 30–35).
> If significant backend changes land after this date, re-verify the
> affected document before relying on it.

## System shape (one paragraph)

Three deployed Workers form the backend: **`apps/api`** (Hono REST API, one D1
database `DB`, KV caches, R2 backups, a search-sync queue, Workers AI +
Vectorize for discovery, and a service binding to management-api),
**`apps/management-api`** (multi-tenant control plane with its own D1 track
plus the shared platform D1), and **`apps/realtime`** (WebSocket rooms held in
`RealtimeSession` Durable Object instances keyed `{roomType}:{roomId}`).
Cron/queue entrypoints live inside `apps/api` (usage aggregation, credit
expiry, checkout reconciliation, token cleanup, storage snapshot) with
`apps/backup-scheduler` deployed separately from a file in the same source
tree. All persistent data is D1 (SQLite): mixed TEXT-UUIDv7 / INTEGER
autoincrement primary keys, INTEGER unix-millisecond timestamps (`_ms`
convention), money in integer cents, JSON columns for nested payloads.

## Cross-cutting Rust-port guidance

Recurring themes across the docs — read the per-doc "Rust rewrite notes" for
detail:

- **Framework mapping**: Hono middleware order is load-bearing (blanket
  `use("/prefix/*", …)` registered before `.route()` mounts gates everything
  under the prefix — including routes designed to be public; see Bug
  inventory). Reproduce ordering deliberately in axum/worker-rs, don't
  transliterate.
- **D1 atomicity**: there are no session transactions. The code relies on
  (a) `db.batch()` for all-or-nothing statement batches, (b) guarded
  conditional UPDATEs + rows-affected checks (compare-and-swap), and
  (c) hand-written compensating writes. `CreditService` is the cleanest
  reference pattern; market-checkouts' cross-vendor order loop is the known
  gap.
- **Idempotency**: DB-level unique (often partial) indexes on
  `idempotency_key`/`client_mutation_id`; current TS code detects conflicts by
  string-matching driver error prose — in Rust, match the SQLite/D1 error code
  instead.
- **Error envelope**: canonical shape is
  `{success:false, error:{code, message, details?}}`, but three variants exist
  today (CSRF bare string, tenantContext sibling fields). Standardize on the
  canonical one; health/monitoring endpoints intentionally return bare
  payloads.
- **Auth**: JWT (per-app claims documented in api-core/realtime/management-api
  docs), bcrypt cost 10 for passwords, roles 0–5. UUID v7 is the stated convention
  for new IDs, but enforcement is uneven: management-api uses v4
  `crypto.randomUUID()` pervasively (licenses, health checks, provisioning,
  onboarding), the partnerships schema uses dash-stripped v4, and several
  tables get service-layer v4 or ad-hoc IDs — see shared-packages.md's
  per-table PK notes and management-api.md before assuming v7 anywhere.
- **Timestamps**: INTEGER unix **milliseconds** everywhere (`timestamp_ms`);
  one confirmed seconds-unit bug exists (soft-delete, below). In Rust, use a
  millisecond newtype rather than raw i64 to make the units unmixable.
- **Cloudflare-specific pieces** with no drop-in Rust equivalent: Durable
  Objects (workers-rs supports DOs; alternatively a stateful WS service), D1
  FTS5 trigram search (discovery), Workers AI + Vectorize (semantic
  discovery), Cloudflare R2 (menu image pipeline is client-orchestrated via
  `apps/image-processor`).
- **Consolidation opportunities**: four divergent encryption schemes → one;
  three copies of the coupon guarded-increment SQL → one; two BackupService
  implementations → one; duplicated `/auth` password-reset flows → one.

## Bug inventory (found & verified during this audit)

Real defects in the current system, confirmed by direct code inspection.
The Rust rewrite should *decide* on each (fix, drop, or intentionally
preserve) rather than port them blindly. File references are in the linked
docs.

> **Remediation status (2026-07-24)**: all 35 items were remediated in the
> TypeScript codebase (see the fix commit touching this line), with these
> qualifications:
> - **#29 is obsolete** — Cloudflare Images has been de-scoped in favor of R2,
>   so the production Images account-hash placeholder and deploy gate were
>   removed.
> - **#6** turned out to be two (not three) genuine method+path collisions —
>   verification's `GET /verify-email` never collided with authentication's
>   POST; the two shadowed POST handlers were removed from verification
>   (zero behavior change), which also resolves the colliding half of #25.
> - **#4/#5** were fixed by deleting the blanket gates — every protected
>   route already carried per-route auth; the unreachable `orders/guest*`
>   routes were deleted (live path is `/guest-orders`).
> - **#13** compensation is best-effort by design (D1 has no distributed
>   transactions): failures surface as session status
>   `requires_manual_review` + loud logs. While fixing **#18**, the
>   pre-existing `db.transaction()` wrapper was found to be non-functional
>   on D1 (rejects BEGIN/SAVEPOINT) and was replaced with `db.batch()`.
> - **#19**: the stale `skipPaths` entry was removed; the 410 tombstone
>   routes themselves are intentional and kept.
> - **#22** deletions were each re-verified zero-reference before removal;
>   three candidates were intentionally **kept**: `useGroupOrder.ts`
>   (live type-only importers), `useOptimizedWebSocket.ts` (its only test
>   exercised the file itself; deleted 2026-10-07), and the `@makanmasak/queue-service` package
>   (workspace-level decision deferred).
> - **#20**: encryption/compression now wired into backup create/restore
>   (key = existing `ENCRYPTION_KEY` secret; hard error if enabled without
>   a key). Decrypt-on-download of encrypted backups remains a follow-up.
> - **#24**: the server shape was taken as truth; only the client-side
>   `orderApi.ts` type was wrong and was aligned.
> The per-doc prose below describes the PRE-fix state the Rust rewrite
> would otherwise have ported — read it together with this status block.

**Realtime delivery (realtime.md, api-features-realtime-misc.md)**
1. Order/kitchen broadcasts target DO rooms `restaurant:{id}`/`kitchen:{id}`,
   but the admin dashboard connects to `admin:{id}` — admin dashboards never
   receive order events over WS. (Kitchen display is unaffected.)
2. Group-order events broadcast to `group_order:{id}`, a room no client can
   ever connect to; `RealtimeSession` has no `GROUP_ORDER_*` handling.
3. Admin-dashboard client calls `/broadcast/*` and `/stats/*` on the realtime
   worker — routes that don't exist (a test asserts the 404).

**Auth & routing (api-core.md, api-features-ordering.md, api-features-identity-tenant.md)**
4. Blanket `use("/orders/*", …)` auth gates group-orders' intentionally
   anonymous share-code join/cart/split routes, and makes `orders/guest*`
   unreachable for guest tokens (the working path is `/guest-orders`).
5. Blanket `use("/seats/*", authMiddleware)` defeats the designed-public
   `GET /seats/qr/:qrCode` (tables does this correctly per-route).
6. `/auth` route collision: authentication's fully-implemented "placeholder"
   handlers shadow verification's `POST /forgot-password`, `/reset-password`,
   `/verify-email` (first-registered wins in Hono).
7. `ingredients` routes check role but not restaurant ownership — any shop
   owner can read/write another restaurant's ingredients.
8. `VerificationService` generates OTPs with `Math.random()`; the customer
   module correctly uses CSPRNG rejection sampling.
9. `management-api` `/licenses/verify` requires a management bearer token its
   only caller never sends — currently latent because that caller
   (`apps/api` LicenseService) is dead code.

**Money & data correctness (api-features-commerce.md, shared-packages.md, api-features-platform-ops.md)**
10. `packages/ai-analytics` filters `orders.status = 'completed'` in 7
    places, a value that does not exist in `ORDER_STATUS` — those analytics
    return zero rows. (`AIInsightsService` raw SQL also references
    non-existent columns.)
11. `SoftDeleteService` writes `deletedAt` in unix **seconds** to
    millisecond-convention columns.
12. Billing webhook HMAC compared with `!==` (timing side-channel);
    market-checkouts/credits use constant-time compares.
13. Market-checkouts vendor-order creation loops `createOrder` per vendor
    with no compensating action on partial failure.
14. `shared-types` numeric enums (`OrderPaymentStatus`, `OrderItemStatus`)
    disagree with the TEXT string columns actually in the DB.
15. Semver strings compared lexicographically throughout management-api
    (`"1.10.0" < "1.2.0"`).
16. `monitoring.ts` alerts query joins `health_checks h ON h.id = t.id`
    (should be `h.tenant_id`).

**Non-functional / dead features (per-doc "surprises" sections)**
17. POS refund completion & receipt printing rely on `setTimeout` without
    `waitUntil` — likely never runs on Workers; rows stick in
    `processing`/`pending`.
18. Scheduling swap-request approval never reassigns the schedule row —
    approval changes nothing on the roster.
19. `features/sse` returns HTTP 410 everywhere (dead by design — real
    streaming lives in kitchen); stale rate-limit config still references it.
20. Backup encryption/compression flags are persisted but the implementing
    code is never invoked by the create/restore pipeline.
21. Management-api `VersionSyncService` never writes the progress key that
    its progress endpoint reads (always 404), and `AlertService` there is
    unimported.
22. Dead code inventory: `apps/api` top-level `LicenseService`/
    `qrCodeService`, `KVUsageService`, `@makanmasak/queue-service` (zero
    dependents), `BackupSchedulerService` (zero production callers — the
    real cron drives the legacy top-level `BackupService` instead, see
    api-features-platform-ops.md), `RegionFormatterFactory` in queue-core
    (never imported; the live receipt formatters are in
    `ReceiptFormatterFactory.ts`), assorted unused methods listed per doc.

**Frontend-contract hazards (frontend-*-contract.md)**
23. Two incompatible WS message-type systems coexist in `shared-types`
    (`websocket.ts` — mostly UPPER_SNAKE, though its last five "前端用"
    types are already lower_snake — vs `realtime-events.ts` lower_snake).
    The only live WS consumer (customer-app order tracking) understands only
    the lower_snake `RealtimeEventType` values — a Rust realtime worker
    emitting the other convention would silently stop order-status updates.
24. `GET /orders/:id/receipt` is called by two customer-app modules
    (`orderApi.ts:585`, `customerOrderApi.ts:121`) expecting mutually
    incompatible response shapes — pick one contract before porting.
25. Customer-app still routes to six legacy password/verification endpoints
    its own auth store calls "retired". Verified against apps/api: two of
    them (`POST /auth/forgot-password`, `POST /auth/reset-password`) land on
    the shadowing authentication-module handlers from item 6; the other four
    (`GET /auth/verify-email`, `POST /auth/verify-email/send`,
    `GET /auth/reset-password/verify`, `POST /auth/guest-token`) have a
    single, unambiguous handler and are unaffected by the shadowing.

**Image pipeline (image-processor.md)**
26. `checkFileSize` only inspects the `Content-Length` header and passes when
    it's absent — a request omitting the header bypasses the size limit.
27. No server-side reconciliation exists for image uploads
    orphaned when the client crashes between "upload succeeded" and "menu
    item write-back" — the cron job cleans logs/jobs but never sweeps
    orphaned images.
28. `GET /analytics/export` is a stub returning a fabricated `download_url`
    on `api.makanmakan.com`, a domain this worker doesn't serve.
29. Obsolete: production Images account-hash placeholder. Cloudflare Images
    has been de-scoped, so this item is no longer applicable.

**Found during the adversarial verification pass (2026-07-24)**
30. `apps/api`'s weekly log cleanup **never fires**: the dispatcher checks
    `event.cron === "0 3 * * 0"` (`apps/api/src/index.ts:65`) but the
    trigger is declared `"0 3 * * SUN"` (`wrangler.toml:292`, whose own
    comment notes CF rejects `DOW=0`) — the strings never match, so
    `cleanupOldLogs` is unreachable in every environment.
31. Guest self-cancel doesn't clear the active-order lock for anonymous
    guests: order creation keys the lock as `anon:{clientIp}` when
    `phoneLastDigits === "000"`, but self-cancel reconstructs the key from
    `phoneLastDigits` directly (`guest-orders/routes/index.ts:342-348`) —
    anonymous guests stay locked out for the full 2-hour TTL after a
    successful cancel. (Admin cancel uses the reverse-lookup key and is
    unaffected.)
32. Admin-dashboard `DELETE /orders/:id` double-wraps its body (wire payload
    `{"data":{"reason":…}}` via `ApiServiceCompat.delete`), and the server
    ignores the body anyway, hardcoding `"Cancelled by user"` — the cancel
    "reason" feature is non-functional end to end.
33. Admin-dashboard `exportGroupOrders()` omits `responseType: "blob"`
    (unlike the three market-checkouts exports), so the group-orders CSV
    export is JSON-parsed by axios and broken client-side.
34. `GET /info`'s endpoint map is stale — it omits `/discovery`, `/markets`,
    `/feedback`, `/billing`, `/manager`, `/audit-logs`, `/customer`, all of
    which are mounted.
35. Scheduling's clock-record CSV export fills the "Employee Name" column
    with `r.employeeId` (a UUID, not a name)
    (`scheduling/routes/index.ts:477-518`).

## How to use this set for the rewrite

1. Start from [api-core.md](api-core.md) (bindings, middleware, mount map) and
   [shared-packages.md](shared-packages.md) (schema inventory) — together they
   define the workspace-level Rust crates you'll need.
2. Port feature-by-feature using the feature docs' route tables as the
   contract, cross-checked against the two frontend contract docs (fields
   clients actually read are the true compatibility surface).
3. Treat each Bug-inventory item as a decision checkpoint in the port plan.
4. Batch 2/3 apps (image-processor, print-agent, remaining frontends) need
   their own docs before their turn.
